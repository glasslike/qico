# qico — FTN-мейлер

`qico` — FTN-мейлер. Он звонит по аутбаунду, принимает входящие сессии и держит сокет управления для `qcc` и `qctl`. Протоколы — EMSI и, если Binkp собран, Binkp, по модему или TCP/IP.

Поведение ниже соответствует фактическим исходникам. Язык конфигурации описан в `qico.conf.sample`.

## Запуск

```
qico [-d | -f | -a тип | -c[NIA] | -n | -t | -T] [-b] [-i хост] [-I файл] [узел] [линия]
```

| Опция | Значение |
|---|---|
| `-d` | демон. Уходит в фон и звонит по аутбаунду |
| `-f` | тот же цикл, но на переднем плане |
| `-a тип` | ответить на одну входящую сессию. `auto`, `emsi` (также `**emsi` или `**EMSI_INQC816`) и, если собрано, `binkp` |
| `-c[NIA]` | позвонить `узлу` сейчас и выйти. См. [Один звонок](#один-звонок) |
| `-i хост` | звонок по TCP/IP на `хост`. `узел` обязателен. В очередь демона этот звонок не ставится |
| `-b` | Binkp для `-c` и `-i`. Нет в сборке без Binkp. Без `-b` звонок идёт по EMSI |
| `-n` | собрать индекс нодлиста и выйти |
| `-t` | прочитать конфиг и выйти. Печатает `Config file is OK` либо завершается с ошибкой |
| `-T` | та же проверка, но вывод конфига подробнее |
| `-I файл` | файл конфигурации. Обычная сборка берёт `/usr/local/etc/qico.conf`; `--with-config` или `--sysconfdir` меняют этот путь |
| `-h` | краткая справка по опциям |
| `-v` | версия |

Без режима и без `-i` `qico` печатает справку по опциям и выходит.

Любой режим сначала читает конфиг. Плохой файл сообщается в stderr и, если `masterlog` указывает на файл, дописывается туда. Затем процесс завершается. `address` обязателен. Должен быть задан хотя бы один каталог аутбаунда.

## Демон

`qico -d` — процесс, который делает исходящие звонки. `qico -f` — тот же процесс, оставленный на переднем плане: `-f` только отменяет fork. Второй демон завершается с `another daemon exists`.

Демон просматривает аутбаунд, звонит, когда узлу можно звонить, и слушает `qcc` и `qctl`. Сам он трубку не берёт и входящий IP не принимает. Входящая сессия — это отдельный `qico -a`, его запускают getty, mgetty или inetd.

Исходящий модем включён, только если в конфиге есть хотя бы одна строка `port`. Без строк `port` демон последовательный порт не открывает; IP-звонки по хостам из `subst` по-прежнему уходят. Входящий аналоговый вызов (`qico -a`) строки `port` не использует.

## Ответ

`qico -a тип` проводит сессию, уже подключённую к его стандартному вводу-выводу, и завершается.

| `тип` | Сессия |
|---|---|
| `auto` | пробовать EMSI. Любой тип, кроме `emsi` и `binkp`, делает то же |
| `emsi`, `**emsi`, `**EMSI_INQC816` | EMSI, без начального обмена |
| `binkp` | Binkp. Только если Binkp собран |

## Один звонок

`-c` и `-i` делают один звонок этим процессом и выходят. Это не заявка уже работающему демону. Поставить звонок в очередь демона можно через `qctl -p` или `qcc`.

```
qico -c[NIA] zone:net/node[.point] [линия]
qico -i хост -b zone:net/node[.point]
```

Буквы после `-c` можно сочетать:

| Буква | Действие |
|---|---|
| `N` | обычный звонок. Заменяет уже выбранные флаги |
| `I` | immediate: не проверять рабочее время узла |
| `A` | любой свободный порт: не проверять `cancall` |

`линия` необязательна и считается с 1. Без неё qico выбирает линию сам.

`-i хост` звонит на этот хост по TCP. Адрес узла всё равно нужен. `-b` выбирает Binkp; без него звонок идёт по EMSI. Имя хоста для этой команды из `subst` не берётся.

## Нодлист и проверка конфига

`qico -n` пересобирает индекс нодлиста и выходит.

`qico -t` и `qico -T` только загружают конфиг. `-T` — подробный вариант. Конфиг, который не разбирается, или конфиг без аутбаунда завершается с ошибкой, а не строкой `Config file is OK`.

Ключевые слова, блоки `if` и `include` описаны в `qico.conf.sample`. Две формы времени оттуда: `Txy` — это UTC, числовой диапазон вроде `01:20-20:15` — местное время.
