# qctl — управление демоном qico

`qctl` отправляет одну команду уже запущенному демону qico и завершается. Сам почту не принимает и звонок не делает. Демон уже должен работать (`qico -d` или `qico -f`). Выход из `qctl` мейлер не останавливает.

Это тот же сокет управления, что у `qcc`. Поведение ниже соответствует фактическим исходникам.

## Запуск

```
qctl [-P порт] [-a хост] [-w пароль] <команда> [узел ...] [файлы ...]
```

| Опция | Значение |
|---|---|
| `-P порт` | порт демона. По умолчанию служба `qicoui` или порт **60178** |
| `-a хост` | хост. По умолчанию `localhost` |
| `-w пароль` | пароль. `-w-` спрашивает пароль в терминале |
| `-h` | краткая справка по опциям |
| `-v` | версия |

Если демон требует пароль, а его нет, `qctl` завершается. Первый ответ демона должен прийти за несколько секунд.

Уходит только одна команда. Если указано несколько командных опций, используется последняя.

Адрес узла — `zone:net/node[.point]`, та же строка, которую разбирает демон. `qctl` не дополняет пропущенные зону и сеть так, как это делает строка адреса в `qcc`.

## Команды без узла

| Опция | Действие |
|---|---|
| `-q` | остановить демон |
| `-Q` | пересканировать аутбаунд |
| `-R` | перечитать конфиг. Открытые сессии продолжаются. Конфиг, который не разбирается, завершает демон |
| `-o` | напечатать очередь |

`-o` печатает таблицу: адрес, объём почты, объём файлов, число попыток и те же буквы флагов, что в очереди `qcc`.

## Poll, удаление, информация

| Опция | Действие |
|---|---|
| `-p[flavor]` | создать poll для каждого следующего узла, затем пересканировать очередь |
| `-K` | удалить аутбаунд каждого следующего узла так, будто он уже отправлен |
| `-f` | информация из нодлиста по одному узлу. Печатаются адрес, станция, место, сисоп, телефон, флаги, скорость и рабочее время |

После `-p` и `-K` можно перечислить несколько узлов. `-f` берёт один узел.

Буква flavor необязательна и пишется вплотную к `-p`:

| Буква | Файл flavor |
|---|---|
| `n` | normal, `.flo`. То же, если буквы нет: `pollflavor` демона, по умолчанию `n` |
| `c` | crash, `.clo` |
| `d` | direct, `.dlo` |
| `h` | hold, `.hlo` |
| `i` | immediate, `.ilo` |

`qctl -p 2:5020/104` берёт `pollflavor`. `qctl -pi 2:5020/104` — immediate-poll. После poll демон снимает с узла флаг immediate, если он стоял.

## Запрос файла и отправка

```
qctl -r узел файл ...
qctl -s[flavor] [-k] узел файл ...
```

`-r` запрашивает эти имена файлов у `узла`. Имя с пробелом передаётся одним аргументом; демон снимает окружающую пару кавычек.

`-s` прицепляет каждый файл к `узлу` с flavor, указанным после `-s`. Буквы те же, что у `-p`. Без буквы flavor снова берётся `pollflavor`.

Каждое имя проверяется на машине, где запущен `qctl`: это должен быть обычный читаемый файл. Относительное имя превращается в полный путь. Демон потом открывает тот же путь, поэтому удалённый `qctl -a` сработает, только если демон может его прочитать. Имя, не прошедшее проверку, пропускается.

`-k` вместе с `-s` помечает файл к удалению после успешной передачи. Если файл не доступен на запись, он всё равно прицепляется, и предупреждение говорит, что удалён он не будет.

## Состояние узла

```
qctl -x буквы узел
```

Заглавная буква ставит флаг, строчная снимает. В одном `-x` можно записать несколько букв.

| Буква | Смысл |
|---|---|
| `U` / `u` | undialable / снять его и обнулить счётчик попыток |
| `W` / `w` | пауза на всё / снять все паузы |
| `I` / `i` | immediate / снять immediate |

Это не hold на время. Hold на N минут — клавиша `h` в `qcc`.

## Разрыв сессии

`-H tty` просит демон повесить трубку сессии, чьё имя в lock-файле равно `tty`. Демон посылает SIGHUP процессу из этого lock-файла.

Проверка, которая для других команд требует узел, выполняется и здесь. Один `qctl -H ttyS0` печатает справку по опциям и запрос не отправляет. Следующее за опциями слово эту проверку удовлетворяет и именем tty не является; имя tty — аргумент `-H`.
